# 阶段 7：逐步增加复杂度

[返回开发总览](../development-workflow.md) · [日常开发流程](daily-workflow.md)

## 目标

按实验需求扩展物理效应，同时保持模型可验证。

## 前置条件

基础模型和实验流程已稳定，已有可持续运行的回归算例。

## 实施内容

基础算例稳定后，再根据实验需求加入风扰、执行器动态、绳索松弛、弹性和碰撞。
每增加一种物理效应，都要补充模型假设、状态或事件定义、独立算例和回归测试。
重新评估积分方法与步长，不默认固定步长 RK4 适合所有后续模型。

## 已记录的可选扩展设计

| 方向 | 设计与默认行为 | 验收重点 |
| --- | --- | --- |
| 吊载等效阻尼 | [Zhu 等 SPAD 解析](../zhu-2025-payload-model.md)；DragConfig 默认零系数，显式选择线性/二次/含 SPAD 的组合 | 系数量纲、速度参考、耗散、张力、关闭退化与数值换向 |
| 控制输入 | [控制接口](../control-and-response-models.md)；C++ 接收实际总推力＋力矩，Python 提供 CTBR、单旋翼及受约束分配 | 指令单位、内环、旋翼编号/力矩符号与分配限幅 |
| 响应与延迟 | 独立选择理想、一阶推力/力矩或电机转速响应，另配纯命令延迟 | 解析阶跃、仿真时间队列、采样周期、复位及失败原子性 |
| 降阶闭环模型 | 后续仅对 CTBR 提供辨识后的角速度响应近似，显式标记 `rate_response` | 与完整刚体的偏差及外力矩/惯性变化时的适用限制 |

C++ 的 SPAD/风场与 Python 的控制分配/延迟/执行器一阶响应已实现；降阶闭环、转速驱动和其他扩展仍处于设计阶段。SPAD 是绳长不变条件下的等效耗散，不等于真实弹性模型；与独立关节摩擦或材料阻尼同时启用时，应防止重复计入同一效应。
CTBR 输入类型、内环算法和执行器动态在 Python 配置，物理积分算法属于 C++，不合并成一个含糊的“仿真方法”开关。

## 交付与验收

新增效应有独立验证，原有算例仍通过；适用范围和精度限制在文档中可查。
