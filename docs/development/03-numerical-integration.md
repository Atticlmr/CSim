# 阶段 3：开发数值积分模块

[返回开发总览](../development-workflow.md) · [日常开发流程](daily-workflow.md)

## 目标

实现通用固定步长 RK4，并用解析解验证精度和收敛性。

## 当前状态与扩展路线

[积分算法调研与预留接口](../numerical-integration.md) 已比较自适应、辛、刚性及约束/李群积分方法。
`include/csim/numerics/` 已预留 RK4、Euler/RK2、Dormand–Prince/DOP853、辛 Euler/Verlet、Radau/BDF、RATTLE 和李群积分入口。
Euler、中点/Heun RK2、辛 Euler、Verlet、[RK4](../rk4.md) 和 [Dormand–Prince 5(4)](../dormand-prince.md) 已实现并接入适用物理模型，见 [使用说明](../integrators.md)。其余复杂方法仍保留占位或前置声明。
数值算例和子阶段循环均在 C++ 验证，积分算法不导出到 Python；Python 只调用后续物理仿真接口。
基础显式和辛方法已接入阶段 4 的物理模型；自适应子步保持外部物理时钟与 Python 控制独立。隐式、约束和李群方法按后续物理需求推进。

## 已完成的 RK4 里程碑

- [x] 通用单步模板，固定控制输入，四阶段时间与状态检查。
- [x] 有限性、时间分辨率、溢出和模型异常处理。
- [x] 指数衰减、自由落体、恒定机体角速度的解析解对照与收敛记录。
- [x] 明确通用积分器不归一化，姿态算例在完整一步后可选归一化。
- [x] 七组 C++ 检查、误差输出与 CI 注册。

接口、局限与测得误差见 [RK4 文档](../rk4.md)。此验收不代表无人机动力学或自适应算法已实现。

## 已完成的 Dormand–Prince 里程碑

- [x] 接受/拒绝、误差策略、步长限制、重试次数与指定时间边界。
- [x] 拒步和失败不提交状态，支持 reset 和控制变化。

首版不提供 FSAL 缓存、连续输出或事件根定位。后续先建立物理模型，再决定这些扩展的优先级。

## 前置条件

阶段 2 已提供积分状态所需的向量运算及独立测试能力。
当前已具备四元数分量算术和 `derivativeBodyRate(Omega_B)`，可用于恒定机体角速度的解析解对照。

## 实施内容

在 `numerics/` 中实现固定步长 RK4。动力学接口约定为输入时间 `t`、状态 `x` 和控制输入 `u`，输出状态导数 `dx/dt`。
积分器只推进状态，不包含无人机、绳索或控制器的专用方程。
明确一个积分步内控制输入是否保持不变，以及 RK4 各子阶段如何计算状态导数。
积分子阶段和状态运算在 C++ 中完成；Python 通过后续具体模型与仿真接口调用，避免把每一步基础运算都跨语言执行。

先用指数衰减、自由落体等有解析解的方程，在 `tests/numerics/` 验证。
在相同终止时刻比较步长 `h`、`h/2`、`h/4` 的误差；用指数衰减等能体现积分误差的平滑问题检查 RK4 的收敛阶。

随后使用恒定 `Omega_B` 验证姿态解 `q(t) = q(0) * fromAxisAngle(Omega_B, |Omega_B| * t)`（零角速度单独处理）。
明确完成一步后是否归一化姿态，并分别记录模长漂移与旋转误差；不要归一化状态导数。
通用积分器不能假定默认构造即为零值：`Quaternion{}` 是单位旋转，零导数为 `Quaternion{0, 0, 0, 0}`。

## 交付与验收

积分接口、实现、解析解对照算例和步长收敛记录；结果在合理误差容限内，减小步长后误差按预期下降。
