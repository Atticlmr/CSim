# 阶段 5：建立可重复的仿真实验

[返回开发总览](../development-workflow.md) · [日常开发流程](daily-workflow.md)

## 目标

建立以 Python 脚本为主要入口的可重复仿真实验、数据记录和结果对照流程，计算循环由 C++ 执行。

## 前置条件

阶段 4 已有通过独立验证、可用于实验的物理模型。

## 实施内容

在 `simulation/` 实现固定步长循环、状态管理和结果记录，在 `configs/` 保存机体与场景参数。
通过 pybind11 暴露模型/运行数据创建、控制、`step(model, data)`、重置和 `get_state(model, data)`；只导出仿真层，不导出数学运算或积分器。具体签名随状态类型确定。
Python 脚本在 `examples/python/` 组织实验、扫描参数、保存 CSV 和绘图；`apps/simulator/` 保留最小 C++ 入口。
先验证无窗口运行和数据导出，再接入图形交互。

先支持一次调用推进一个物理步并读取独立状态快照；按需要再增加一次调用批量推进多个物理步。长计算期间根据线程安全约定释放 GIL，明确同一仿真实例能否并发访问。
轨迹采用批量数组接口，约定形状、时间顺序、`double` 精度以及复制/共享内存的生命周期。
需要 Python 控制回调时，规定调用频率、控制保持策略和异常终止行为，不默认在每个 RK4 子阶段回调。
当前单摆、无吊载无人机和绷紧吊载耦合已提供模型/数据、step、get_state 和 reset 以及 Python 示例；无人机已加入 set_control，默认理想总推力和机体系力矩在完整时间步内保持；Python ControlLoop 可配置 CTBR、单旋翼及执行器响应/延迟。耦合模型已提供两端加速度、绳索张力与受力快照；创建和重置需显式初始推力。Python 已可输出显示用 CSV 和参数/代码版本 JSON，并由 viewer 回放；URDF/MJCF 固定模型加载已实现，批量数组接口仍待实现，见 [Python 开发指南](../python.md)。

后续多控制模式与执行器接入遵循 [控制与响应设计](../control-and-response-models.md)：分别记录目标指令、延迟后生效指令和实际力/力矩，由 Python 使用整数物理步管理控制周期及延迟队列。
物理快照保留当前线/角加速度等派生量，积分状态另行明确；不要让 Python 自行积分电机状态或更新 PID 内部历史。

显示轨迹录制的操作和范围见 [可视化文档](../visualization.md)。完整状态/控制器存档仍按下述实验记录要求扩展；显示 CSV 不能用于恢复积分状态。
飞控闭环运行另见 [PX4/APM 在环设计](../flight-controller-integration.md)，不让 Python 或 viewer 成为硬件同步时钟。

每次运行至少保存：

- 本次参数、初始状态、积分方法、步长、仿真时长和代码版本；引入随机扰动后记录随机种子。
- 时间、位置、速度、姿态、吊载状态、张力和控制输入。
- 必要的约束误差、能量误差及异常终止原因。
- 控制输入模式、控制器参数、各级采样周期、响应模型、时间常数、延迟与饱和配置。
- 启用 SPAD 时记录系数组合、系数来源、速度/风场约定、sign 或 tanh 模式及平滑速度尺度。

在 `tests/simulation/` 验证终止时间、输出数量和异常处理。
在 `tests/python/` 验证同一初值和输入通过 Python 与 C++ 得到一致轨迹，并检查参数转换、结果生命周期和失败传播。
长期用于对照的基准算例放入版本管理，批量运行结果与临时数据独立存放，并配置相应忽略规则。

已新增 `hover.py`、`tracking.py` 和 `payload_swing.py`，内外环均在 Python，C++ 只推进物理。
示例支持实时 Viewer、无窗口、显示间隔、JSON 指标输出和抑摆反馈对照，见 [控制与响应](../control-and-response-models.md)。

## 交付与验收

同一配置可重复运行，结果在约定容差内一致；Python 可独立完成一次实验并获取轨迹，可以比较不同步长或代码版本下的结果。
