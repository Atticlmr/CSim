## 实施内容

按以下顺序推进，每个模型通过独立算例后再进行耦合：

| 顺序 | 模型 | 验收重点 |
| --- | --- | --- |
| 1 | 固定悬点的单摆 | 小振幅周期、无阻尼时的能量误差、绳长约束 |
| 2 | 无吊载的无人机 | 自由落体、悬停力平衡、力矩与姿态响应 |
| 3 | 无人机与吊载耦合 | 张力方向、作用力与反作用力、连接点力矩、绳长约束误差 |
| 4 | 控制器与轨迹跟踪 | 悬停稳定性、跟踪误差、控制输入限幅及不同初始摆角下的响应 |

耦合模型先完成无阻尼验收，再接入默认关闭的 `linear / quadratic / linear_spad / quadratic_spad / integrated_spad` 选项。
依论文建立摆角对照模型，核心仍使用单位绳方向；验收包括阻力耗散、非零径向阻力下的张力、风速定义与换向处的数值行为。
没有原始实验数据时，不把模型间比较写成已复现论文辨识精度。

Python 控制支线按 `wrench` → CTBR 角速度内环 → 单旋翼推力与控制分配推进，执行器响应和纯延迟分别验证。
完整刚体状态继续保存位置、速度、姿态和角速度，加速度由力重算；执行器动态增加的是 Python 层的实际推力或电机转速等状态。
加入任一模块时同步维护模型/数据/step/get_state 边界，不把底层数值接口暴露给 Python。

方程推导放在 `docs/`，回归测试放在 `tests/dynamics/`，可重复运行的算例放在 `examples/`。
模型验证后，在仿真层组织类似 `step(model, data)` 的步进、控制及状态快照，再通过 `bindings/python/` 导出并添加 Python 算例；模型导数和底层运算不直接导出。
模型方程与验证基准仍由 C++ 核心维护，Python 配置实验并分析结果。
能量和约束检查应给出数值容差及其随步长变化的情况，不要求浮点积分结果精确守恒。

## 交付与验收

每个模型有明确假设、受力说明和独立验证结果；耦合后仍能解释状态变化、张力及误差来源。
